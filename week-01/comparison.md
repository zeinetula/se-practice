## 3. What the AI added that I never asked for

- Added an interactive web UI with full CSS styling and a file upload button.
- Added client-side visual charts to display mark distribution graphs.

## 4. What the AI got wrong or silently skipped

- **Failed to filter invalid inputs (Case B):** It included negative numbers (`-5`), numbers above 100 (`101`), and parsed non-numeric strings as zeroes instead of ignoring them.
- **ZeroDivisionError crash (Case D):** When provided with only invalid inputs (`abc, , xyz`), it attempted to compute the average of an empty array, crashing the program instead of outputting a clear warning message.

## 5. The defect I asked Rocket to fix

**Prompt I used:**
"Fix input validation: ignore negative numbers, numbers greater than 100, and non-numeric strings completely. If no valid marks remain, print 'No valid marks found' without crashing."

**Result:** Fixed.

**What this tells me:**
AI tools often default to standard "happy path" logic and require explicit user instructions to handle edge-case validation and guard clauses properly.

## 6. Reflection (200–300 words)

The AI genuinely sped up the initial scaffolding and visual setup of the project. Generating a baseline script took only a few seconds, which drastically reduced the time spent setting up boilerplate code, basic function declarations, and standard user interface elements.

However, the AI cost me significant time during validation and debugging. The code generated on the first try looked completely correct at first glance, but it failed to handle edge cases properly. It treated invalid inputs such as negative numbers and text strings as valid data points, and it crashed with a division-by-zero error on an empty dataset. Debugging these subtle flaws and crafting precise follow-up prompts took almost as much effort as writing the validation logic from scratch.

Out of the two solutions, I would comfortably put my name on the manual implementation. While the AI version is functional after several revisions, writing the manual program gave me complete certainty over its execution flow, validation boundaries, and error prevention logic.

This experiment proves that a human engineer must remain responsible for overall system safety, specification compliance, and rigorous testing. While AI can act as a fast assistant for drafting code, only a human software engineer can verify edge cases, ensure security standards, and take responsibility for production-ready reliability.
